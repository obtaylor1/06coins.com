2. Add an “SMS Overview” section to the main Admin Dashboard
On the main Admin dashboard:
Add a compact SMS Overview block containing 3–4 metric cards.
Cards:
“SMS Sent Today”
Show total number of SMS messages sent today (all types).
“SMS Sent This Month”
Total count for the current month.
“Delivery Success Rate (Last 30 Days)”
Percentage = delivered / sent for the last 30 days.
“Unsubscribes (Last 30 Days)”
Count of customers who replied STOP or were marked opted-out.
Use the existing card style:
black/charcoal background, gold headings, white text, subtle icons.
If feasible, add a tiny sparkline or mini-line chart for “SMS volume last 7 days” inside the block.
Data source: use the SMS log table/model you already write to (or create one as described in step 3).
3. Create an “SMS Activity & Logs” page
Add a new route & page:
Route: /admin/sms (or /admin/sms-activity)
This page should show a searchable, filterable table of SMS logs.
SMS log model/data
If not already in place, create an SmsLog model or table with fields:
id
createdAt
type (transactional / marketing / admin)
templateName (e.g., orderConfirmation, shippingConfirmation)
orderId (nullable)
customerId (nullable)
phone
status (sent, delivered, failed, opted_out)
providerMessageId (nullable)
errorMessage (nullable)
body (text of the SMS)
Ensure all future SMS sends write to this log.
Table layout
Columns:
Date/Time (createdAt)
Customer Name (if available)
Phone number
Order # (clickable to order detail)
SMS Type (transactional / marketing / admin)
Template
Status (with colored badge)
Short message preview (truncated)
Filters:
Date range picker
SMS type filter
Status filter
Search input (by phone, order #, or customer name)
Row actions:
“View full message” (modal or drawer with full SMS text)
Optionally: “Resend” for admin-only utility, but only for certain types (e.g., orderProblem), with a confirmation step.
Add a link to this page in the Admin navigation, e.g., “SMS Activity”.

On the Order details admin view:
Add a panel titled “SMS Timeline”.
Display all SMS messages associated with that order, sorted newest first.
For each entry:
Timestamp
Type (e.g., Order Confirmation, Shipping, Delivery)
Status icon/badge:
✅ for delivered
➜ for sent
⚠️ for failed
🚫 for opted-out
Short preview of the body (first 80–100 chars)
If no SMS exists for the order, show a friendly empty state:
“No SMS have been sent for this order yet.”
Admin actions in this panel:
A dropdown + button to send a one-off SMS using a predefined template (e.g., “Order problem notice”):
Dropdown: list of valid templates allowed for manual send.
Button: “Send SMS”.
Validate that:
Order has a valid phone
Customer has not opted out (show warning if they have)
5. Add a Customer SMS Preferences panel
On the Customer details page (or create one if needed):
Add a section titled “SMS Notification Preferences”.
Fields to display:
Phone number
SMS order updates opt-in (Yes/No toggle)
SMS marketing opt-in (Yes/No toggle)
Last SMS sent (date + type)
Opted out at (if any)
Admin actions:
Edit phone number (if allowed by your model).
Turn OFF marketing opt-in (never turn ON without explicit consent).
Optionally mark the number as “Do Not Text”.
This is read/write from the same fields used by your SMS sending logic.
6. Add an “SMS Settings & Templates” page
Add a new route & page:
Route: /admin/settings/sms
This page will manage:
Templates
Event triggers
Global rules
Admin alert configuration
6.1 Template List
Display all SMS templates in a list/table:
Columns:
Template Name (e.g., Order Confirmation)
Template Key (e.g., orderConfirmation)
Type (Transactional / Marketing / Admin)
Short description
“Edit” button
6.2 Template Editor
When editing/creating:
Show:
Template name (read-only or editable depending on design)
Template key (read-only)
Type label
Text area for SMS body
Show available variables for that template, e.g.:
{{firstName}}
{{orderNumber}}
{{total}}
{{trackingLink}}
Show a character counter (e.g. “120 / 160 characters”) to help admin avoid overly long texts.
Show a live preview with sample data substituted.
Save changes to a JSON or DB-based template store that the SMS service uses at runtime.
6.3 Event Triggers
On the same page, visualize mappings like:
order.created → orderConfirmation (toggle)
order.shipped → shippingConfirmation (toggle)
order.delivered → deliveryConfirmation (toggle)
order.problem → orderProblem (toggle)
delivered + 2 days → thankYouStory (toggle)
delivered + 7 days → reviewRequest (toggle)
Each mapping should have:
Event name (label)
Template dropdown (select one of the templates)
Enable/disable toggle
Persist this configuration so the backend uses it when sending SMS.
6.4 Global Rules & Limits
Add controls for:
Global kill switches:
[ ] Enable SMS globally
[ ] Enable marketing SMS
[ ] Enable admin SMS alerts
Quiet hours:
Inputs for Quiet hours start and Quiet hours end (e.g., 21:00–08:00).
Helper text: “Non-urgent messages will be delayed during quiet hours.”
Limits:
Max SMS per order per day
Max marketing SMS per customer per month
Store these in a settings config collection or table (e.g., AppSettings.sms).
7. Admin SMS Alerts configuration
In the same SMS Settings page, add a section:
“Admin Alerts”
Fields:
Admin phone number (default: from SMS_ADMIN_NUMBER env; allow override).

These toggles and values should be read by the backend when deciding whether to send admin SMS.
